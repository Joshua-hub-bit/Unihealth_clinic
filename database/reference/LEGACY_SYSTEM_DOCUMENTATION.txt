  1. SYSTEM OVERVIEW
================================================================================

The SUNN Clinic Information System is a web-based clinic management platform
built for the State University of Northern Negros Medical and Dental Services
Office. It replaces manual paper-based processes with a fully digital system.

The system handles:
  - Student health record management (Personal Health Record / PHR)
  - Nurse and physician workflow (consultations, forms, certificates)
  - Admin oversight (staff management, statistics, reports)
  - Medical forms and certificates (Medical Certificate, X-Ray Request,
    Consultation Record, Referral, Prescriptions, Dental, Lactation, etc.)
  - Multi-campus support (Old Sagay, Sagay Main, Laga-an, Escalante)
  - Appointment scheduling
  - Clinic visit logging
  - Medication tracking
  - Inventory management
  - Audit logging

  uvicorn               0.32.1        ASGI web server — runs the FastAPI app
                                      and serves the system on port 8000
                                      Command: uvicorn main:app --port 8000 --reload
  
  Apache HTTP Server    (optional)    Web server for static files — proxies
                                      /api/ requests to the FastAPI server.
                                      Not required; uvicorn can serve alone.

  WHY PYTHON?
    Python was chosen because it is easy to read, has excellent libraries for
    web APIs (FastAPI), and integrates cleanly with PostgreSQL (psycopg).

  WHY PostgreSQL?
    PostgreSQL is a powerful, reliable, open-source relational database.
    It supports complex queries, foreign keys, triggers, and JSON — all of
    which this system uses. It also handles concurrent users well.

  WHY uvicorn?
    uvicorn is the recommended server for FastAPI. It supports async requests
    (multiple users at the same time without slowing down), and has a --reload
    mode for development that auto-restarts when code changes.

  6. DATABASE
================================================================================

  Database System : PostgreSQL 17.5
  Database Name   : sunn_uni_clinic
  Host            : localhost
  Port            : 5432
  Default User    : postgres

  TABLES AND WHAT THEY STORE:
  ─────────────────────────────────────────────────────────────────────────────
  campuses              The 4 SUNN campuses (Old Sagay, Sagay Main,
                        Laga-an, Escalante)

  students              All registered student accounts. Stores name,
                        email, password hash, student ID, course/year,
                        department, contact, address, sex, age, blood type,
                        campus assignment, and profile picture.

  staff                 All clinic staff accounts. Stores name, employee ID,
                        email, password hash, role (nurse/physician/dentist/
                        staff/admin), license number, contact, campus.

  health_records        Personal Health Records (PHR) submitted by students.
                        Contains full medical history: vital signs, symptoms,
                        immunizations, menstrual health, emergency contacts,
                        allergies, family history, blood type, signature.
                        A student becomes a "Patient" once this is saved.

  clinic_visits         Records of each time a student visits the clinic.
                        Stores date, time, reason, symptoms, treatment,
                        vital signs (BP, temp, pulse, RR, O2 sat, weight),
                        attending nurse, disposition, and notes.

  appointments          Appointment bookings. Stores student, date, time,
                        service type, reason, status (pending/confirmed),
                        and which staff member created it.

  medications           Medication tracking per student. Stores drug name,
                        dosage, schedule, purpose, consent status.

  inventory             Clinic supply and medicine inventory. Tracks item name,
                        category, quantity, unit, expiry date, supplier,
                        batch number, minimum stock alert level.

  forms_certificates    All medical forms issued to students (Medical
                        Certificate, Consultation Record, X-Ray Request,
                        Lab Request, Referral, Prescriptions, Dental
                        Certificate, Lactation forms, etc.)

  audit_log             Tracks every significant action in the system:
                        who did what, when, from which IP address.
                        Used for accountability and security review.

  system_settings       Key-value store for system-wide configuration.

  IMPORTANT RELATIONSHIP:
    A student is classified as a PATIENT across all dashboards
    once they successfully save their Personal Health Record (PHR).
    This creates a row in the health_records table linked to their
    student account via student_id (foreign key).

  9. HOW THE SYSTEM WORKS (ARCHITECTURE)
================================================================================

  ┌──────────┐     HTTP/AJAX      ┌────────────────────┐     psycopg3
  │ Browser  │ ──────────────── > │  FastAPI (Python)  │ ──────────────── >
  │ (Chrome) │ < ──────────────── │  uvicorn port 8000 │ < ────────────────
  └──────────┘    JSON response   └────────────────────┘    SQL queries
                                                                   │
                                                        ┌──────────────────┐
                                                        │  PostgreSQL 17   │
                                                        │  sunn_uni_clinic │
                                                        └──────────────────┘

  STEP-BY-STEP FLOW:

  1. User opens browser and goes to http://127.0.0.1:8000
     FastAPI serves index.html (landing page).

  2. User clicks Login — browser loads login.html.

  3. User enters credentials. JavaScript sends a POST request to
     /api/auth.php?action=login with email + password.

  4. FastAPI receives the request, queries PostgreSQL for the user,
     checks the bcrypt password hash, and returns a JSON response
     with user info (name, role, campus, etc.).

  5. JavaScript stores the user info in sessionStorage and redirects
     to the appropriate dashboard (admin, nurse, or student).

  6. auth-guard.js runs on every dashboard page. If no valid session
     is found in sessionStorage, it immediately redirects to login.

  7. The dashboard JavaScript calls the API for data (students, patients,
     stats, etc.). Each fetch goes to /api/admin.php, /api/nurse.php,
     or /api/student.php with ?action=<action_name>.

  8. FastAPI routes the action to the correct Python function, runs
     the database query, and returns JSON. The JavaScript renders
     the data in the UI.

  PATIENT IDENTIFICATION FLOW:
  ─────────────────────────────
  Student registers  →  account created in `students` table (role='student')
         │
         ▼
  Student fills and saves PHR  →  row created in `health_records` table
         │
         ▼
  All dashboards now show this student as a "PATIENT":
    - Nurse dashboard: student appears in the patient list
    - Admin dashboard: "Patient" chip shown, Patients stat increments
    - Student dashboard: "Patient" badge appears in greeting banner

  10. HOW TO RUN THE SYSTEM
================================================================================

  PREREQUISITES:
    1. Python 3.11 or higher installed
    2. PostgreSQL 17 installed and running
    3. The sunn_uni_clinic database created and schema loaded

  SETUP STEPS:

  Step 1 — Create the database (run once):
    Open pgAdmin or psql and run:
      CREATE DATABASE sunn_uni_clinic;
    Then run the full SQL file:
      db/sunn_clinic_postgres.sql

  Step 2 — Install Python dependencies:
    Open a terminal in the project folder and run:
      pip install -r requirements.txt

  Step 3 — Configure the .env file:
    Edit the .env file with your PostgreSQL credentials:
      DB_HOST=localhost
      DB_PORT=5432
      DB_NAME=sunn_uni_clinic
      DB_USER=postgres
      DB_PASS=YourPasswordHere

  Step 4 — Start the server:
      uvicorn main:app --host 127.0.0.1 --port 8000 --reload

  Step 5 — Open the system in a browser:
      http://127.0.0.1:8000

  DEFAULT LOGIN ACCOUNTS (from seed data):
    Student  : student@uni.edu       / password123
    Admin    : admin@sunn.edu.ph     / admin123
    Nurse    : nurse@sunn.edu.ph     / nurse123

  13. SECURITY MEASURES
================================================================================

  PASSWORDS
    - All passwords are hashed using bcrypt (cost factor 12)
    - Passwords are never stored in plain text
    - bcrypt is specifically designed to be slow to resist brute force

  SESSION
    - User session stored in browser sessionStorage (cleared on tab close)
    - auth-guard.js checks session on every page load
    - No session = immediate redirect to login

  INPUT VALIDATION
    - All text inputs are sanitized server-side (sanitize() function)
    - SQL queries use parameterized placeholders (%s) — SQL injection
      is not possible because user input is never embedded directly
      in SQL strings
    - Email addresses are validated with a regex before insertion

  API RESPONSES
    - All API responses include Cache-Control: no-store headers
    - Frontend uses cache-busting timestamps (?_=<timestamp>) on requests
    - This prevents browsers from showing stale data

  FILE ACCESS
    - .env file is blocked by Apache (.htaccess FilesMatch rule)
    - .sql, .py, .log files are blocked from direct browser access
    - Directory listing is disabled (Options -Indexes)

  AUDIT LOG
    - Every significant action (login, save record, add staff, delete,
      print form, etc.) is recorded in the audit_log table with:
        · user ID and type (student/staff/admin)
        · action performed
        · entity affected
        · IP address
        · user agent (browser info)
        · timestamp
